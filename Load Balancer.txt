## 🔍 **Project Title:**  
**Adaptive Load Balancing Using Proximal Policy Optimization (PPO)**

---

## 🎯 **Objective:**  
The primary goal of this project is to develop an **intelligent, adaptive load balancer** using **PPO (Proximal Policy Optimization)**—a reinforcement learning algorithm—that outperforms traditional methods by:

- Reducing **response time** and **latency**  
- Minimizing **server overload** and **crash risks**  
- Ensuring better **resource utilization** and **scalability**

---

## 🧠 **Motivation:**  
Traditional load balancing techniques such as **Round Robin**, **Least Connections**, or **Randomized Assignment** often fall short when:

- The request rate is **highly dynamic**
- Server health and performance vary over time
- **State awareness** (like current load, response latency, failure rate) is required for optimal balancing

This led to the use of **Reinforcement Learning (RL)**, specifically **PPO**, which learns optimal policies through interaction and feedback.

---

## 🛠️ **System Architecture:**

### 1. **Central Grid-Optimized Model (Initial Phase):**
- A **baseline model** using a **Multilayer Perceptron (MLP)** that takes server parameters like:
  - CPU usage
  - Memory availability
  - Latency
  - Throughput
  - Health score
- Optimizes request distribution using static heuristics and basic neural inference.

### 2. **PPO-Based Adaptive Load Balancer (Core Component):**
- Implements PPO to dynamically learn request assignment policies.
- Takes into account:
  - Number of servers
  - Number of incoming requests
  - Learning rate
  - Clipping ratio

---

## ⚙️ **Methodology:**

### ✅ **Input Parameters (from User):**
- Number of servers
- Number of user requests
- Learning rate (`lr`)
- PPO clip ratio (`epsilon`)

### 🔁 **Simulation Loop (Per Iteration):**
1. Each server is initialized with its own metrics.
2. The central PPO agent:
   - Observes the state of all servers
   - Takes actions to assign requests
   - Receives rewards based on:
     - Request success rate
     - Server performance (low latency, high throughput)
     - Penalty for overload/crash
3. Logs:
   - Server status per iteration
   - Assigned requests
   - Request completion time
   - Rewards and policy improvement metrics
4. Generates:
   - Iteration-wise visualizations (load heatmaps, line graphs)
   - Log files (in JSON or CSV)
   - Optional GIF animations for server request flow

---

## 📊 **Metrics Collected:**
- **Average request runtime**

- **Server health metrics**
- **Reward progression** (learning curve)
- **Crash protection index** (how well server overloads were avoided)

## 🧪 **Analysis & Results:**
- The PPO-based model learns **adaptive policies** that outperform static ones.
- Dramatic **reduction in response time and latency** under high load.
- **Crash incidents reduced** due to smarter distribution decisions.
- Can be scaled to **multi-agent scenarios** where each server runs its own PPO instance.

## 📈 **Research Implications:**

- Provides a base for future **multi-agent reinforcement learning** systems.
